## 1. Resumo

Artigos podem ser escritos em Markdown no campo `Conteúdo`. A tela apresenta uma barra de ferramentas local, prévia rápida e a mesma formatação na revisão e na leitura de publicações, sem alterar o fluxo obrigatório de revisão e confirmação.

## 2. Contexto

O editor de rascunhos aceitava somente texto puro. A revisão exigida pela RFC-002 continua necessária para verificar a publicação imutável, mas não substitui o retorno imediato que uma pessoa espera ao formatar um trecho.

## 3. Decisão

- A barra Markdown existe somente no campo `Conteúdo` de artigos; título e comentários não recebem ferramentas de edição.
- Cada ação insere sintaxe Markdown e um exemplo selecionado para substituição. A implementação usa índices de seleção do `textarea`, sem marcador persistido ou operação global de substituição, evitando colisões com o próprio conteúdo.
- A prévia rápida é opcional, local e não salva o rascunho. A etapa `EM_REVISAO` permanece obrigatória e é a prévia final somente leitura antes da confirmação de publicação.
- O renderizador suporta títulos, ênfase, riscado, citações, listas, links `https`/`http`, código em linha, blocos de código e linhas horizontais. HTML inserido no conteúdo é exibido como texto; não é interpretado.
- Ícones SVG inline acessíveis são usados porque não há fonte de ícones empacotada e uma dependência remota contrariaria o uso offline.

## 4. Alternativas consideradas

| Alternativa | Decisão |
|---|---|
| Apenas avançar para a revisão | Rejeitada: aumenta o custo de experimentar a formatação e exige salvar antes de enxergar o resultado. |
| Prévia rápida e revisão obrigatória | Escolhida: dá retorno imediato sem enfraquecer a confirmação explícita e a imutabilidade. |
| Renderizar HTML informado pelo autor | Rejeitada: introduz risco de execução de conteúdo não confiável nas cópias que importam uma publicação. |

## 5. Segurança e compatibilidade

O corpo continua texto local e publicado pelo formato existente; não há migração, arquivo adicional, dependência de rede ou alteração no protocolo. O renderizador escapa HTML e gera somente as próprias tags. Links aceitam exclusivamente os esquemas `http` e `https`, com `noopener noreferrer`.

## 6. Critérios de sucesso

- [x] O campo `Conteúdo` de artigo oferece ferramentas Markdown com exemplos selecionáveis.
- [x] A prévia rápida não persiste nem altera o estado do rascunho.
- [x] A revisão obrigatória e a leitura do Acervo mostram a formatação Markdown com segurança.
- [x] HTML e esquemas de link não permitidos não são interpretados.
